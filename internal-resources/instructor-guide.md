<h1>
  <span class="headline">Intro to Git, GitHub, and GitHub Flow</span>
  <span class="subhead">Instructor Guide</span>
</h1>

This module introduces GitHub flow in a step-by-step manner. You should stick to the process presented in the lecture material so that students come away with the most relevant Git commands/workflow. This lecture is not intended to make people masters of Git or GitHub, and there is important information about both that is intentionally not provided as part of this lecture. In other words - it's a jumping-off point, not the whole mountain.

Students should follow along with an instructor as they work through the content to get some practice doing GitHub flow independently.

Git and GitHub are very common pain points for students. Encourage them by reinforcing that they will need to do this many times before they start to grasp the process. Also, remind them that much of the Git vocabulary is new to them. On top of learning the process they also have to learn the language of the process, making it even more challenging.

This messaging may be useful if students find the activity in the [Handling Merge Conflicts](../handling-merge-conflicts/README.md) lecture challenging. You may want to take a pulse check of the classroom as you approach the end of the activity. If a good portion of the class is done or almost done you may want to extend the time a little for them to finish up. On the other hand, if most students are struggling to complete the activity you may want to step in early and do a walkthrough of the expected result instead.

More concretely, you should also suggest that students bookmark the provided [Cheat Sheet doc](../cheat-sheet/README.md) to reference as they get used to GitHub flow. It has all the steps and commands we present in the lecture with as little framing copy as possible so that they have a concise document to reference as they're doing the GitHub flow the first few times on their own.
